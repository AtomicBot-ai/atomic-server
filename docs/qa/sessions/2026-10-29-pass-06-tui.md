# Exploratory QA — pass 06: terminal state transitions after B14–B16

## Charter

Explore the fixed TUI with real installed engines, synthetic chats and attachments, a second authenticated client and terminal resizing to discover inconsistent state, lost intent and unreachable recovery paths.

## Plan and oracles

1. Change model, engine and chat during a load and after a failure. A late completion must not replace a later model/chat choice; Cancel/Retry must lead somewhere usable.
2. Edit engine settings, cancel, navigate away, and change the same settings through another client. Draft values must not silently become saved values or overwrite newer changes.
3. Exercise chat parameters, attachments, failed sends, New chat, deletion and another client's generation. Compare the screen with durable history and the server's operations.
4. Repeat important transitions using keyboard-only navigation at 120×40 and 54×24. Controls must remain reachable and input must reach the intended field.

Use existing reports to deduplicate findings. Confirm and minimize candidates before assigning IDs from B17. This pass is discovery only: no product fix, dependency change, commit or external ticket.

## Environment

macOS arm64; core 0.19.1; binary built from `ec52295` plus the uncommitted B14–B16 fixes on `codex/tui-qa-fixes`. A fresh `atomic-qa-tui-pass06-*` data folder and separate app-data folder contain APFS copies of previously installed official engines and downloaded models. API/admin use ephemeral loopback ports; update checks and telemetry are off. No production data or OS service is used.
