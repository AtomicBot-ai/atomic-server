# 2026-11-07 — Share web settings field geometry and accessible descriptions

- **Context:** Web settings mixed full-width inputs, intrinsic-width selects and widely separated label/control rows. Attachment settings also coerced empty numeric drafts to zero and allowed edits during a save.
- **Decision:** Use `SettingsField` for native controls, with a shared label, hint, unit, error and stable ID. Settings pages use one aligned control column; compact forms use the same component with labels above controls. Numbers use a short input, text and selects fill their column, and multiline fields span the available width. Rows stack according to their form container width, including drawers and nested panels. A 760px reading measure and a bounded label column keep fields near their labels on desktop. Field actions stay with their control. Native selects retain keyboard behavior with an inset decorative chevron; forced-colors mode restores the native arrow.
- **Consequences:** `Controls.Field` delegates native children to the common component while preserving composite controls. Server, runtime, engine, assistant, connector, provider and Playground forms share the geometry without changing their persistence contracts. Attachment settings group documents, retrieval and images, retain string drafts, validate before saving and freeze controls until the request finishes. Repeated unchanged snapshots cannot replace an acknowledged local save. Media sliders pair a separately named range with a labelled numeric field and share its error description; dimensions and audio hints use the same native field component. Connection guides, command forms and small chat dialogs use bounded containers and separated action rows. Nested command objects use fieldsets rather than nested labels; JSON errors describe their editor. Message editing, reminder registration, confirmation dialogs and the standalone admin sign-in reuse the same field geometry. The sign-in surface supplies theme tokens without depending on the workspace shell. Legacy media forms keep their existing reachability. Shared save bars preserve each form's own restart and apply rules.
- **Alternatives:** A global width on every input would break search, media and composer layouts and make short numbers unnecessarily wide. Replacing native selects with a custom dropdown would introduce keyboard and focus behavior unrelated to the layout fix. Existing small forms retain stacked labels rather than forcing all controls into horizontal rows.
