# 2026-10-29 — Pin core 0.20.5 and keep revision-based chat saves

- **Context:** Atomic Server embedded core 0.19.1. The owner requested 0.20.5 and fixes for failing tests. An existing working-tree change removed the blanket prohibition on saving messages during an active generation, leaving a test that still required refusal.
- **Decision:** Pin `@atomic-chat/core` to exactly 0.20.5, update `bun.lock`, release documentation and generated third-party notices. Keep the removed active-generation prohibition as explicitly requested by the owner. Test that history operations forward the explicit expected revision, fall back to the loaded revision, and propagate storage conflicts unchanged. Exclude nested `.claude/worktrees/` checkouts from the root formatting check and format the twelve existing source files it flagged without changing behavior.
- **Decision:** Wait for the first skill to appear before navigating the long Tools menu: the popup can open before its asynchronous `features.get` snapshot arrives, so early arrows traverse an empty list. Reproduced with `CI=true` after failures on Linux x64/arm64 and macOS. Synchronize resize and navigation with Ink's public `waitUntilRenderFlush()` instead of empty React `act()` boundaries. Keep the last-skill visibility and toggle assertions intact; do not increase timeouts or skip platforms.
- **Decision:** Teach the shared fake host only the owner-ACL commands and the core ACL read-back protocol. Fail-closed startup now awaits that check on Windows; the old fake rejected every command and therefore blocked otherwise unrelated daemon contract tests. Unknown commands still fail and no real system program is run by the fake. Keep production permission checks unchanged.
- **Decision:** In the first-model PTY regression, wait for the asynchronous device summary before using label coordinates, both on entry and on Back. Its arrival inserts rows above the cards, so a click against the earlier layout can select the neighbouring model. Keep the final persisted-model assertion and include the terminal transcript when it fails.
- **Decision:** Import the Windows PowerShell security module by its `$PSHOME` path before checking Authenticode, with terminating errors. A parent PowerShell 7 session can provide an incompatible module search path, causing the update E2E to receive no signature status. Keep the same trust policy: unreadable probes refuse updates, unsigned binaries are recognized only from an explicit `NotSigned` result.
- **Decision:** Await the actual focus target in the web connection retry regression. Model readiness can render before the separate focus-restoration effect runs; checking focus immediately after the Configure button becomes enabled races that effect. Both failed-retry and successful-retry focus assertions remain required.
- **Decision:** Allow 60 seconds for the server to publish its core endpoint. The previous 20-second budget excluded the now-awaited owner-only ACL checks; Windows arm64 E2E logs show a healthy server becoming ready after the command had already failed. Preserve early reporting when the spawned process exits and explicit timeout overrides. A regression advances the core wait clock through 50 seconds without sleeping on wall time. Reject an absent auto-load model before asking for engine catalogs, so an irrelevant slow catalog does not delay its warning.
- **Decision:** The owner explicitly authorized merging and releasing 0.2.9 before resolving the remaining Windows arm64 test infrastructure failures. Only the v0.2.9 release gates and native build E2E omit `workspace-documents.test.ts` on Windows arm64; its explicit 30-second limit expired after a successful slow startup. A custom reporter accepts only the exact observed Vitest `onTaskUpdate` reporting timeout and throws on every other unhandled error. Assertion failures still fail. Normal PR/main CI and later release tags retain the full suite. Signed binaries, checksums, installation smoke tests and package publication remain mandatory. Follow-up work must restore complete Windows arm64 coverage and remove this one-release exception.
- **Consequences:** The core adds its transitive `smol-toml` dependency; no direct runtime dependency is added. History saves remain guarded by the existing cross-process revision check in `ChatHistory`, rather than whether a generation is active. The core's version check requires an updated server process when attaching after upgrade. Nested worktrees keep their own formatting responsibility.
- **Alternatives:** A version range could silently change the embedded protocol and is forbidden by the release policy. Restoring the active-generation prohibition would undo the owner's chosen behavior. Formatting another checkout from this repository's root would modify unrelated work.
