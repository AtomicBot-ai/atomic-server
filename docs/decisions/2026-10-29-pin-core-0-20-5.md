# 2026-10-29 — Pin core 0.20.5 and keep revision-based chat saves

- **Context:** Atomic Server embedded core 0.19.1. The owner requested 0.20.5 and fixes for failing tests. An existing working-tree change removed the blanket prohibition on saving messages during an active generation, leaving a test that still required refusal.
- **Decision:** Pin `@atomic-chat/core` to exactly 0.20.5, update `bun.lock`, release documentation and generated third-party notices. Keep the removed active-generation prohibition as explicitly requested by the owner. Test that history operations forward the explicit expected revision, fall back to the loaded revision, and propagate storage conflicts unchanged. Exclude nested `.claude/worktrees/` checkouts from the root formatting check and format the twelve existing source files it flagged without changing behavior.
- **Decision:** Wait for the first skill to appear before navigating the long Tools menu: the popup can open before its asynchronous `features.get` snapshot arrives, so early arrows traverse an empty list. Reproduced with `CI=true` after failures on Linux x64/arm64 and macOS. Synchronize resize and navigation with Ink's public `waitUntilRenderFlush()` instead of empty React `act()` boundaries. Keep the last-skill visibility and toggle assertions intact; do not increase timeouts or skip platforms.
- **Decision:** Teach the shared fake host only the owner-ACL commands and the core ACL read-back protocol. Fail-closed startup now awaits that check on Windows; the old fake rejected every command and therefore blocked otherwise unrelated daemon contract tests. Unknown commands still fail and no real system program is run by the fake. Keep production permission checks unchanged.
- **Consequences:** The core adds its transitive `smol-toml` dependency; no direct runtime dependency is added. History saves remain guarded by the existing cross-process revision check in `ChatHistory`, rather than whether a generation is active. The core's version check requires an updated server process when attaching after upgrade. Nested worktrees keep their own formatting responsibility.
- **Alternatives:** A version range could silently change the embedded protocol and is forbidden by the release policy. Restoring the active-generation prohibition would undo the owner's chosen behavior. Formatting another checkout from this repository's root would modify unrelated work.
