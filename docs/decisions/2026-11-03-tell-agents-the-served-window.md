# 2026-11-03 — Tell launched agents the served window

- **Context:** The desktop's QA 2.3.2 audit found that agents told nothing about the window assume 128K-272K and never compact before a 16K-64K local server refuses, and that a window smaller than an agent's own prompt and tools fails every turn. The desktop and the core's agent writers now write the served window into each agent's settings and refuse a terminal agent below 32,768 tokens (Atomic-Chat 344cc5a42, 42543bb8c, 34c152968, 573b10f5d, ff9694147, 6533e144c; atomic-chat-core 82d4139 and the writers after it). From the next core, `GET /v1/models` names each local model's window (`context_length`, llama-server's `meta.n_ctx`; core cdff199). The same audit found that an npm agent on Windows is a `.cmd` shim Node refuses to spawn without a shell (core e3a9707); `atc connect` and the terminal UI spawn the path `findOnPath` returns, which is that shim.
- **Decision:** `prepareAgent` and `connection.profile` read the model's window from the API's own `/models`. When it is known, the one-run profiles carry it: Claude Code `CLAUDE_CODE_MAX_CONTEXT_TOKENS` and `CLAUDE_CODE_MAX_OUTPUT_TOKENS` (a quarter, at most 8192), Codex `model_context_window` and `model_auto_compact_token_limit` (three quarters), Atomic Agent `userModels[].contextWindow`, OpenCode 1.x the model's `limit`; a known window under 32,768 refuses with `ATC_USAGE` before any profile is written. Unknown (a core that does not advertise it, an unreadable list), nothing is written and nothing is refused. Claude Code also gets `CLAUDE_CODE_DISABLE_TERMINAL_TITLE`, and OpenCode 1.x `reasoning`, `interleaved: reasoning_content` and no SDK timeouts, as the core's writers do. On Windows a `.cmd`/`.bat` launcher, and OpenCode's version probe, run through `cmd.exe /d /s /c "<line>"` with each token quoted for cmd, the core's rule.
- **Consequences:** On core 0.20.7 profiles are unchanged apart from the terminal title and OpenCode's model fields; the window arrives with the core pin that advertises it. The server does not grow a model's window as the desktop does: with "Fit context to device memory" on by default the engine already serves the widest window that fits, so the refusal names the setting to turn off instead. OpenCode 2's provider schema is not checked here, so its profile keeps only the name. The 19 agents the guide configures by hand get no window from the server.
- **Alternatives:** Growing the context and reloading on Connect would fight the fit default and reload a model other clients use. Importing the core's writers is not possible: `integrations/configure` is not exported, and they edit the user's own config files, which the server never does.
