# 2026-11-03 — Pin core 0.21.0 for agent serving

- **Context:** Core 0.21.0 (atomic-chat-core#68) serves coding agents better: `GET /v1/models` advertises each local model's window (`context_length`, `meta.n_ctx`), an overflow on `/v1/messages` answers "prompt is too long", mid-conversation system messages stay in place for llama.cpp, request finish fields carry `ctx_len` and `cached_tokens`, and llama.cpp defaults to two shared-KV slots, continuous batching and an automatic answer cap; vLLM and SGLang pick their window and request count. The server's agent profiles and Activity (`2026-11-03-tell-agents-the-served-window.md`) read those fields. A build of that branch passed `npm run verify` here without changes. 0.21.0 does not carry the tensor-count correction the server has patched into 0.20.7 since #69 (atomic-chat-core#67 is open).
- **Decision:** Pin `@atomic-chat/core` 0.21.0 exactly. Carry the tensor-count correction as `patches/@atomic-chat%2Fcore@0.21.0.patch` (the same `errors.js` change; 0.21.0's file is byte-identical to 0.20.7's), and drop the 0.20.7 patch and the copied core source diff, which atomic-chat-core#67 replaces.
- **Consequences:** On first start the core moves stored settings still at an old default once (llama.cpp parallel 1 → 2, continuous batching on, `n_predict` -1 → 0; vLLM and SGLang context 8192 → automatic, requests 1 → automatic), a user's deliberate 1 or 8192 included. A request without `max_tokens` is capped at 16,384 tokens, never more than the window. Remove the patch once a core release carries #67. No engine ran in these checks.
