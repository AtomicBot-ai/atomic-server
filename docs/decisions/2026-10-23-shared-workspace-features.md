# Shared assistants, connectors, skills and document settings

Status: accepted and implemented. The owner explicitly approved all three parser dependencies on 2026-10-23.

## Context

The desktop controls previously led to unavailable capability placeholders in the server frontends. The user requested functioning desktop workflows and the same state in Web and TUI. The reference is `atomic-chat-ui` at `807b4d9`. It contains the frontend and Tauri invocation contracts, but not its native service implementations. These client features are outside the inference core's public exports.

## Decision

The authenticated workspace service owns a private, atomically updated document for assistant presets/defaults, Markdown skills, MCP configuration and attachment settings. Frontends use the same registered operations and snapshot. MCP secrets are masked in snapshots; OAuth tokens stay in a separate private server document.

Assistant instructions and selected enabled skills enrich inference requests on the server. User selections remain in conversation request settings; internal selection fields never reach inference. TUI local conversations use the same server-owned cancellable chat jobs as Web. Connector tool calls require explicit review and approval in each frontend. Saving a connector does not launch a process. Explicit connection performs initialization and tool enumeration through stdio, Streamable HTTP or legacy SSE. Browser OAuth uses discovery, dynamic registration, PKCE, state validation, a loopback callback and refresh tokens.

Text documents support bounded inline processing, explicit lexical excerpts, or real embeddings generated by a running core embedding model through the public `/embeddings` endpoint. Exact cosine search is used; it does not claim to implement an ANN index. Image sizing happens locally in the browser before upload.

## Binary documents and portable skills

The following exact dependencies were approved by the owner and are recorded in `bun.lock`:

- `pdfjs-dist@4.8.69`: extract PDF page text through the supported PDF.js API. Reject encrypted or image-only documents with an actionable message; OCR is outside this change.
- `fflate@0.8.3`: bounded ZIP reading/writing for portable `.skill` archives and modern Office containers, without native dependencies.
- `fast-xml-parser@5.11.2`: parse DOCX paragraphs, XLSX worksheet/shared-string values, and PPTX slide text from those containers. Do not execute macros, formulas, external entities or embedded objects.

The parsers enforce upload byte limits, 256 archive entries and a 64 MB expansion limit, reject path traversal and XML entities/document types, and parse in memory. Skill resources are retained in portable packages without execution; shared snapshots expose resource names only. PDF processing disables evaluation and rendering, caps page/text counts, and uses a statically bundled in-process message handler. Only extracting a PDF loads PDF.js. Its optional canvas and path rendering packages are not used.

PDF.js 6.4.299 requires `Promise.try` in its modern build and fails on the supported Node 22 baseline. Version 4.8.69 runs the same tested text path under Node and a compiled Bun binary without runtime branching, canvas or a worker file. The 2026-10-23 Bun advisory audit lists no advisories for the three approved packages; existing development/core transitive advisories remain separate from this feature change.

Tests cover malformed/truncated archives, traversal and ZIP expansion, XML entities, legacy `.doc`/`.xls` rejection, multi-page PDFs, DOCX, shared-string XLSX, PPTX, skill resources, and Node/Bun single-binary extraction. Image-only PDF OCR and legacy Office binary conversion are explicitly unsupported with actionable errors.

These are text extractors, not document-layout parsers. DOCX reads main-body paragraphs; XLSX reads stored values without recalculating formulas or applying number/date display formats; PPTX reads slide text without notes. Worksheet and slide files use numeric filename order, not custom order from workbook/presentation relationship metadata. Headers, footers, comments, visual layout, images and OCR are outside this implementation. Skill frontmatter supports single-line name/description fields; packaged resources are preserved for export, not executed or attached as model tools.

Automatic attachment mode uses a character-count threshold rather than the actual loaded model's token budget. Larger documents require a running embedding model; exact cosine retrieval has no persistent ANN index. Shared chat enrichment applies to the local server endpoint; the terminal's explicit remote-endpoint fallback still streams directly. The detailed bounds and automated evidence are recorded in [the annotation-pass review](../keyboard-mouse-e2e.md#annotation-pass-shared-settings-and-document-ingestion).

## Consequences

Both frontends now edit the same functioning features. The browser and terminal retain local drafts while snapshots synchronize saved values. PDF, modern Office and text attachments pass through shared configured ingestion. Web uploads or downloads portable skill packages; TUI reads or saves a user-chosen file path without silently overwriting files.
