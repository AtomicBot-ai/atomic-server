# 2026-11-07 — Reuse the API listener when connecting an agent

- **Context:** Web and terminal Connect loaded the model and then unconditionally restarted a running API. On Windows, a minimal Bun 1.3.14 executable reproduced a listener remaining busy after HTTP shutdown while a child process spawned after listening was alive; terminating that test child freed the port. The affected atc reported a stopped API while Windows still attributed port 1339 to its process.
- **Decision:** Both connection guides use the shared `connectionApiOperation` selector. An unchanged host and port use the core's idempotent `api.start`; an explicitly changed listener still uses `api.restart`. The restart warning follows the same selection.
- **Consequences:** Connecting an agent no longer tears down a healthy listener or interrupts its requests. Core still validates the complete start configuration and owns the listener. This does not fix Windows runtime socket inheritance: an explicit restart with live child processes can still fail; an already affected process needs recovery before retrying Connect.
- **Core dependency:** The accompanying core lifecycle fix permits repeated start after host key rotation: an active dynamic keyring overrides the static start key, so that unused key alone cannot make the listener incompatible. Static-key-only servers still reject changed keys. This fix is in the local core used by the preview binary; the npm dependency pin is unchanged.
- **Follow-up:** The underlying Windows socket inheritance is addressed by [pinning the corrected runtime](2026-11-07-prevent-windows-socket-inheritance.md). Reusing an unchanged listener remains desirable because it avoids interrupting requests.
- **Alternatives:** Disabling the busy-port check would hide real conflicts without releasing the inherited socket. Restarting the engine on every Connect would interrupt inference unnecessarily. Neither is used.
- **Validation:** Targeted web and terminal regression tests cover reuse; selector tests cover stopped, unchanged, and changed listeners. The Windows socket reproduction used only a temporary port and a disposable child process, without models.
- **Windows preview:** The rebuilt preview (admin build `95716d319d45db46`) loaded the existing `unsloth/Qwen3-0.6B-Q4_K_M` through `llamacpp-upstream`, reused the same running API on 1339, passed the connection's model-response verification and API ping. No models were downloaded; the original data folder and admin port 55582 were preserved.
