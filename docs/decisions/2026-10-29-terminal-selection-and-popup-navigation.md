# 2026-10-29 — Order terminal selections and navigate complete popup menus

- **Context:** Follow-up TUI QA found B17–B19 and a remaining B16 variant. A local load could finish after a new connection was saved and overwrite it; editor errors were hidden behind the editor itself; navigation used only visible Tools targets; other clients persisted a full MLX build ID while TUI displayed one provider row.
- **Decision:** A validated endpoint begins the same selection revision and serialized preference queue as local/remote model choices. Invalidate stale load callbacks immediately and serialize already-started writes before the new endpoint/model pair. Keep strict URL validation before invalidation and guard delayed completion/failure against newer intent. Generic editors display the existing action error inside their bounds; opening an attachment editor and successfully attaching a document clear the previous message, while pointer movement preserves a visible editor error. Drawing and keyboard/wheel navigation share a complete Tools row list, with headings excluded from focus and the viewport following it. Resolve an exact engine build first, then an explicit provider row; only a provider-only preference may fall back to the active build reported by core.
- **Consequences:** A newer connection survives a late local load without losing the draft. The old server-owned load may still complete and remains observable in server state; changing client selection does not unload it. Errors appear where the user can correct them. Skills and connectors remain reachable beyond the first screen, including compact terminals, with footer controls and exit preserved. Full non-llama IDs stay compatible without changing the shared preference format or guessing a missing llama.cpp build. Multi-key preference writes remain separate operations; this guarantees ordering within one TUI controller, not a cross-client transaction.
- **Alternatives:** Merely checking callback freshness leaves an already-started stale config write racing the new one. Saving an address outside the existing queue recreates that race. Removing version checks or stopping a server-owned model to change client intent would change unrelated concurrency semantics. Navigating rendered targets alone makes hidden rows unreachable. Normalizing all saved engine IDs to providers would discard an explicit llama.cpp build selection.
