# 2026-11-01 — Add audio.cpp before the core pin has it

- **Context:** The core's audio module (`/atomic/v1/audio/*`, the `audio-cpp` engine) is on atomic-chat-core#61, unreleased, and conf's `models/audio.json` on atomic-chat-conf#44, not merged. atc pins core 0.20.5, which has no audio types, no `audio-cpp` in `ENGINE_KINDS` and no audio routes. The server should follow how it wraps image generation, without waiting for the release and without bumping the pin to one that does not exist.
- **Decision:** Build the feature against a local copy of the contract (`src/contract/audio.ts`), with `engineKind` naming `audio-cpp` as an engine of builds. At run time a core without audio is recognised by its answer, "no such control route" on `/audio/*`: `audio.*`, an `audio-cpp` install and an audio `artifacts.plan` refuse with one sentence (`ATC_NOT_IMPLEMENTED`), and the snapshot records `audio_available: false` with no error, so clients offer no playground task, setup goal or catalog category. The route is the test rather than the pinned `ENGINE_KINDS`, because a client may attach to a server another build left running. Catalog: `models.catalog` keeps `category: audio`, read through `fetchConfList` (remote, cache, bundled copy), the bundled file being conf's verbatim. A download uses `ArtifactService` with one file in `<data>/audio/models/<filename>`, the load names it by file name, and the plan keeps `audio {mode, attribution, controls, defaults, ranges}` beside the load so clients draw a model's form and notice from catalog data on disk, never from its id. `audio.generate` fills a missing `durationSec` for music and effects from the loaded model's catalog default, because the engine alone can make minutes of audio; a model's `default_voice` goes into the load, because Qwen3-TTS refuses a request without a voice. The web admin gets a small studio; the terminal UI opens `audio.generate` on the shared operation runner.
- **Consequences:** Nothing changes on 0.20.5: the engines list stays the core's, and the real-core contract test holds that. Every piece that must change with the pin is marked `core-workaround: … until core 0.21.0`, so lint fails once the pin moves: replace the copies with core imports, drop `noAudioCore`, `audio_available` and what hides audio without it. If the release is numbered below 0.21.0, those markers must be changed to that version. No audio path has run against a real engine from atc yet. The terminal UI has no studio, and a reference voice cannot be uploaded from the web studio; `audio.generate` takes both voices and `voiceRef`.
- **Alternatives:** Bumping to an unreleased core would break install and CI. Hiding the feature behind a build flag leaves it untested and adds a state nobody uses. Reading `ENGINE_KINDS` only says what was compiled in, not what the attached server runs. Extending `media.*` would mix sd.cpp's job and gallery shape with audio's, and the core keeps them apart too.
