# 2026-10-28 — A key is checked where it is used; Send waits for a download; one word for a paused download

- **Context:** The 0.2.5 end-to-end report (two clean profiles, Web and terminal) confirmed four defects
  fixed here. B01: an invalid OpenRouter key was marked Connected, because `cloud.connect` checked only
  `GET /models`, which OpenRouter serves to anyone. B03: the terminal sent a message while the model was
  still downloading, leaving an empty "No text returned." answer; its readiness check skips endpoints
  that differ from the API address in the snapshot, and the terminal's endpoint can differ while still
  being this server (a port set only in the server's environment, or changed after the terminal opened).
  B02: the shared download card said "cancelled" for a paused transfer that the Downloads list called
  Paused. B04: the terminal's connection guide accepted port 70000 and refused it only at Configure.
- **Decision:** `cloud.connect` also sends an empty `POST /chat/completions` with the key after the model
  list: 401 or 403 means the key is refused, anything else (a valid key gets 400) means it is taken. The
  terminal blocks Send for a model this server is still downloading, whatever its endpoint, and a failed
  turn drops the empty answer it opened. Every client names a download's state with one function,
  `downloadStateLabel`: held by a person is Paused. The guide checks the port when it is saved and on
  Continue, keeps what was typed for correcting, and the field's hint says what a port is.
- **Consequences:** One more request per provider check; it generates nothing. A provider that reports a
  bad key as 400 on an empty chat request, with a public model list, still passes. A separately connected
  endpoint whose model id matches one downloading here waits for that download. The terminal's endpoint
  can still differ from the server's API address after a download finishes; Send then goes to that
  address. That drift is its own fix (the terminal should take this server's address from the server).
- **Alternatives:** OpenRouter's own `/key` endpoint: fixes one provider, while other gateways also serve
  a public model list. Treating every loopback endpoint as this server: a person's own Ollama on
  localhost is not this server, and its readiness is not ours to judge.
