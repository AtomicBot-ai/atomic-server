# 2026-10-29 — Guard shared edits and preserve model recovery boundaries

- **Context:** Exploratory QA B01–B13 found data loss from stale chat copies, disappearing browser drafts, inconsistent MLX discovery/installation state, and permissive input paths. The user authorized fixes for every finding owned by Atomic Server. B05 is an engine crash and remains outside this repository.
- **Decision:** Persist a monotonically increasing conversation revision under the existing cross-process document lock; identical saves are no-ops and return the current revision. Web generation and history saves carry the loaded revision; reject stale edits before writing or generating. Legacy generation clients without a revision may append only to the complete current message prefix. Explicit revisions permit intentional editing and regeneration. Keep composer drafts in per-tab session storage with an in-memory fallback. Preserve the first-run model selection in the wizard and resolve it to its installed row after download.
- **Decision:** Merge matching curated catalog rows with format-correct Hub search results. MLX uses the Hub's MLX filter; uncurated MLX installation requires MLX metadata and the existing immutable, complete-checkpoint plan. Register verified MLX downloads before publishing ready. Migrate older ready jobs once, checking files and recording that registration completed so later explicit removal is not undone. Use the core's public ModelRegistry and setting descriptors; do not copy engine selection or compatibility policy.
- **Decision:** Validate preset types, numeric bounds and enum membership against the core descriptors before staging and before forwarding settings updates. Show unsupported existing values explicitly. Keep form validation errors separate from background refresh errors. Validate API prefixes as literal URL-safe paths in every config input. A skill create/import must not replace an existing name; edits identify the existing skill explicitly. Search conversation text rather than serialized message keys. Bound history import by the existing 32 MiB file size rather than 100 conversations, validating the complete batch before writes; retain the 2,000-message limit per conversation. The PTY test helper owns TERM for the terminal it creates.
- **Consequences:** Stale clients receive a recoverable conflict instead of silent data loss; they must reopen before retrying. Existing chat documents start at revision zero and need no file migration. Invalid previously accepted API prefixes are now rejected with a correction hint. A browser with unavailable session storage still retains drafts in memory, but cannot recover them after reload. Imported skills with colliding names require an explicit edit or another name. Import remains bounded by file size and per-conversation size; I/O failure during writes can still leave a partially imported batch, as before. No dependencies, commits, services or production data changes are needed.
- **Alternatives:** Automatically merging a stale request cannot reliably distinguish a deliberate edit from missing newer turns. Hiding a completed MLX job until first load or patching only the chat picker leaves clients inconsistent. Re-registering every ready job on every startup resurrects removed models. Splitting imports into independently saved groups leaves later invalid entries after earlier groups have already been written. Hardcoding valid engine options would drift from the core schema. Prism CPU fallback does not fix its Metal assertion and is not presented as a product fix.
