## Help texts

### atc start

```
Usage: atc start [options]

The server keeps running after this command; `atc stop` ends it. With --foreground it stays in this process instead — for Docker and systemd — and stops on SIGTERM or Ctrl+C.

Options:
      --admin              Serve the web admin (--no-admin to skip) (default: true)
      --admin-port <port>  Admin port for this server
      --foreground         Stay in the foreground (containers, systemd); SIGTERM stops it

Global options:
  --json                Print the result as one JSON document (errors go to stderr as JSON)
  -v, --verbose         Debug-level logging on stderr
  -q, --quiet           Only errors on stderr; no progress
  -y, --yes             Answer yes to safe confirmations; required for elevation and deletion
                        without a terminal
  --data-folder <path>  Data folder to work with (default: <system data>/atomic-chat-cli/data)
  --no-color            Disable ANSI colours (NO_COLOR is honoured too)
  -h, --help            Show help
  --version             Print the version
```

### atc run

```
Usage: atc run <model> [options]

Loads the model on the active engine — the one running now, else engines.default — and makes it answer on the API. It downloads and starts nothing else: a missing model, server or engine is an error that names the command to run first (`atc models pull`, `atc start`, `atc engines install`). `atc unload` stops it; the desktop app calls these Run and Stop.

Arguments:
  <model>  Model id, as `atc models list` shows it

Options:
      --engine <engine>  Engine to run it on (llamacpp-upstream, llamacpp, mlx or tensorrt-llm);
                         remembered as engines.default
      --embedding        Start it in embedding mode

Examples:
  atc run qwen3-8b
  atc run qwen3-8b --engine mlx

Global options:

  -v, --verbose         Debug-level logging on stderr
```
